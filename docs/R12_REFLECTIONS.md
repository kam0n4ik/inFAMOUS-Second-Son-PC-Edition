# R12 — отражения игры: механизм, цена и пункт «Качество отражений»

Агент **refl**, ветка `feature/r12-refl` (от `3dd34db`), worktree `E:\SecondSonPC-r11-postfx`.
Сырые данные: `E:\research\r12\runs\refl\` (`ghidra/`, `diag1..5/`, `b1/`, `b2/`, `tools/`).
Метки: **[E]** измерено, **[A]** анализ (Ghidra / дизассемблер), **[H]** гипотеза.

## 0. Итог

- **Отражения в игре — это смесь пяти механизмов [A][E].**
  - Экранные отражения (SSR, проход 12).
  - Планарное отражение воды (проход 16).
  - Планарные отражения по плоскостям (проход 18): в проверенных сценах их нет.
  - Карты отражений: статические зонды окружения и «карточки отражений».
  - Мокрота как свойство материала.

  Блики фар и фонарей на мокром асфальте складываются из двух частей:
  - **экранного отражения** того, что видно на экране (сами фонари, вывески, фары);
  - **бликов освещения** на мокром материале. Это зона агента lights.
- **Цена [E].**
  - SSR — 7 отрисовок в 480×270 / 960×540 и композит в 1920×1080, всего **~0,42 мс GPU/кадр** (user и neon, gprof
    вкл./выкл.).
  - Отражение воды — **~380 отрисовок/кадр** вида отражения в 480×270 (user). Но его полное выключение
    (диагностика) **не дало прироста FPS** (серия Б, §4). Значит, рычаги воды не дадут миллисекунд:
    - половинное / четвертное разрешение (HALF_RES_REFLECTIONS);
    - размытие (BLUR_WATER_REFLECTIONS);
    - набор объектов в виде отражения.
- **Отражение воды выключать нельзя [E].** Без вида отражения залив становится **чёрным**. Запасного пути у игры нет:
  шейдер воды читает цель отражения в любом случае (`diag3/water_on_off.png`). Поэтому такого уровня нет.
- **Пункт «Качество отражений»** (меню «Графика» → «Эффекты», под «Размытием в движении»), применяется сразу:
  - **Исходное** — как в игре (по умолчанию);
  - **Низкое (без экранных отражений)** — `SsrPass 0x45a690` не записывается. Это тот же путь, что игра проходит
    сама при `SSR_OPACITY = 0`.

  «Высокое» и «среднее» **не введены**: ни один найденный параметр, кроме выключения SSR, не даёт измеримых
  миллисекунд (§3). По правилу «не добавлять пунктов, которые ничего не дают» уровней два.
- **Тип B, «Низкое» против «Исходного», чередующиеся пары [E]:**
  - user (сумерки, мокро, CP-упор): **32,76 → 33,30 FPS (+1,7 %, по парам +2,4 / +1,7 / +1,6 %)**, P99 35,2 → 34,9 мс.
  - neon (дождь ночью, лужи, фонари; маршрут погони, 6 пар в двух сериях): медиана FPS **51,7 → 55,0**
    (лучше в 4 парах из 6), GPU busy **15,2 → 14,6 мс/кадр** (среднее по прогонам). Долгие кадры **не
    подтверждены**: в b1 они уходили во всех трёх парах (P99 45,1 → 38,5 мс), в b2 — наоборот (P99 39,1 → 43,6 мс).
    Разброс маршрута (±13 % FPS между одинаковыми прогонами) больше эффекта. Обещания про «меньше долгих кадров»
    в подсказке нет.

  Таблицы по каждому прогону — в §4.

## 1. Механизм [A]

Адреса — RVA в eboot.bin (CUSA00004, SELF: смещение в файле = VA + 0x6f30).

### 1.1 Экранные отражения (SSR) — `SsrPass 0x45a690`

- Вызов: только из настройки прохода 12 (`0x191100`, после контекстов теней), аргументы
  `(цели сцены 0xe682b0, контекст, камера)`.
- Условие: флаг отладки `0x7dff160` == 0 (игра его не пишет) **и** `SSR_OPACITY` окружения (`*0x7f8e800 + 0x3c8`) > 0.
  Иначе функция ничего не записывает. В обеих проверенных сценах `SSR_OPACITY = 0,7` [E].
- Шаги и FX-объекты. Классы прочитаны в игре по `vtable+0x40` и таблице имён `0xdace00` [E]:
  1. `0x45a110`, FX `0x7d4c218` / `0x7d4c220` (CFxColorAndDepth): копия HDR-сцены в цель `+0xdaf0` (уровень 3,
     960×540).
  2. FX `0x7d4c228` (CFxColorAndDepth) → `0xe719b4`.
  3. `0x459940`, FX `0x7d4c1f8` (**CFxSsr**): трассировка лучей в `+0x8f78` (уровень 4, 480×270). История прошлого
     кадра — `+0x1aed0`, параметр `SSR_OPACITY` — в слот констант `+0x126`.
  4. `0x4560f0`, FX `0x7d4bed0` (CFxCopyTexture): копия результата в историю `+0x1aed0`.
  5. `0x459940`, FX `0x7d4c200` (CFxSsr): цвет отражения → `+0x87ec`.
  6. `0x45a430` ×2, FX `0x7d4c210` (**CFxSsrBilateralBlur**): разделимое размытие.
  7. FX `0x7d4c208` (CFxSsr): композит с блендингом в HDR-сцену 1920×1080 (тест глубины).
- Число шагов трассировки — в шейдере, не на CPU. Уровни целей — таблица `0x1d0cc4c`:
  `0:1920×1080 … 3:960×540 4:480×270` [E].
- Цели уровня 4 (`+0x87ec`, `+0x8f78`, `+0x9704`) — **общий scratch** с DOF / размытием / bloom / планарными
  отражениями. Менять их размер нельзя.

GPU-отрисовки SSR в профиле (`SSPC_GPU_PROFILE`, исчезают при выключении SSR) [E]:

| пиксельный шейдер | цель | мс/кадр (user) | мс/кадр (neon) | роль [A/H] |
|---|---|---|---|---|
| `0x2edad2e00` | 480×270 fmt 97 | 0,183 | 0,152 | трассировка (CFxSsr) |
| `0x2edaa6500` | 1920×1080 fmt 97, глубина | 0,133 | 0,135 | композит в сцену |
| `0x2edaa6e00` | 960×540 fmt 97 | 0,087 | 0,076 | копия цвета сцены |
| `0x2edaa7d00` | 480×270 | 0,018 | 0,018 | цвет отражения |
| `0x2edaa5300` ×2 | 480×270 | 0,016 | 0,016 | двустороннее размытие |
| `0x2edadd200` | 480×270 | 0,013 | 0,013 | маска |
| `0x2edab2f00` | 480×270 | 0,006 | 0,006 | копия в историю |
| **всего** | | **~0,46** | **~0,42** | |

### 1.2 Планарное отражение воды — `0x5974f0` (проход 16, настройка `0x191760`)

- Менеджер воды `0x7f7a750`: список `{камера, вид CViewReflection (+0x750 — плоскость отсечения), список отрисовки}`.
  Флаг `+0x13db0`.
- Вид отражения рисуется в цель-слот 8 сцены. `0x190090` выбирает её по `HALF_RES_REFLECTIONS` (`+0x3cc`):
  `+0x1890c` (уровень 3) или `+0x19098` (уровень 4). Рисуется так:
  1. контекст с плоскостью отсечения;
  2. отложенный вызов `0x597310`. Он проходит 4 корзины списка вида (37, 38, 9, 10 из таблицы `0xae5750`) через
     `0x43cef0`;
  3. затем в отдельном контексте:
     - блики `0x194060`, режим 0 — объекты с флагом **DRAW_IN_REFLECTION** (зона lights);
     - композит `0x1a5f70`;
     - при `BLUR_WATER_REFLECTIONS` (`+0x3cd`) — размытие `0x191ac0(0,6; 0,9)` в `+0xdaf0` / `+0x87ec`;
  4. в конце игра ставит флаг воды `+0x13db1 = 1`.
- [E] user:
  - `HALF_RES_REFLECTIONS = 1`, вид в 480×270;
  - ~381 отрисовка/кадр одним шейдером `vs 0x2d6637600 / ps 0x2d663c400` плюс мелкие;
  - GPU ≈ 0,1 мс;
  - всего отрисовок кадра 7 500 → 7 100 без воды.
- [E] neon: `HALF_RES_REFLECTIONS = 0`, воды в кадре нет (вызовы есть, отрисовок вида нет).

### 1.3 Планарные отражения по плоскостям — `0x3bfb90` (проход 18)

- Список видов `0x7d37598` (CViewPlanarReflection, `+0x4a8` — активен). Каждый вид — полный проход сцены
  (контексты `0xb54`/`0xb55`), затем копия и размытие.
- [E] **0 активных видов** в user и neon: в проверенных местах не используется.

### 1.4 Карты отражений

- Зонды окружения: `ambient_spec_probes/%s(%s).dds`, FX CFxAmbientSpecular `0x7d4c168`, множитель
  `AMBIENT_SPECULAR_CUBEMAP_MULTIPLIER` (`+0x250`, в обеих сценах 1,0). Статические текстуры: в профиле нет
  кубических целей, которые рисуются каждый кадр [E].
- «Карточки отражений» CReflectionCard (вид класса `0x9a`, vtable `0xd643c0`):
  - менеджер `0x7d44070`, список `0x7d44060`;
  - каждая карточка — 3 текстуры (`0x44a510` из FX `0x7d4bea8`) и объём. Карточки отбираются по расстоянию до камеры,
    сортируются (`0x418290`, из настройки прохода `0x1905e0`) и применяются в отложенном освещении [A].
  - Отдельного прохода с заметной ценой нет.

### 1.5 Мокрота

- `WETNESS_LEVEL +0x348`, `PUDDLE_LEVEL +0x350`; итоговая мокрота `0xe87c80` (геттер `0x598b50`). Подробно — агент
  weather.
- При > 0 идёт проход `0x597ec0` (FX CFxWetnessDeferred `0x7d4c158`) из `0x190c90`: полноэкранная модификация
  G-буфера.
- [E] user: мокрота 0,8 / лужи 0,7; neon: 0,9 / 1,0, `WEATHER_KIND = 1` (дождь).

## 2. Где фары и фонари [A][E]

- **Экранные отражения (SSR)** отражают то, что уже нарисовано на экране: сами фонари, вывески, фары, свечения.
  Это единственная часть отражений фонарей, которую можно отделить без вреда другим эффектам.
- **Блики источников на мокром** — свет материала: `LIGHT_SPECULAR_ENABLED` у света, сеттер `0x271070`. Это зона
  lights, пункт его не трогает.
- **Блики в отражении воды** — объекты-свечения с битом DRAW_IN_REFLECTION (`+0x32c` бит 2, сеттер `0x2e5900`).
  Рисуются только в вид воды, вся цена которого ≤ шума (§4).

Поэтому пункт честно называется **«Низкое (без экранных отражений)»**, а не «без отражений фар»: фонари не гаснут,
и их блики на мокром остаются.

## 4. Тип B (ABBA, база R12: `SSPC_R9_PCACHE=1;SSPC_R9_HEAP_WINDOW=1;SSPC_R10_AJM=native;SSPC_R10_SYSRT=native;SSPC_R11_EARLY_SUBMIT=256`)

Переключатель серий — `SSPC_REFLECTION_QUALITY=original|low` (тот же код, что пункт меню). Пары — порядок ABBA
(`orig, low, low, orig, orig, low`); пара *i* = прогоны `*_i`.

- `b1`: флаг тишины 01:45–02:36, user 3 пары + `wateroff` (диагностика) + neon 3 пары, TDR 0.
- `b2`: флаг тишины 05:51–06:23, neon 3 пары, TDR 0.
- Окно user 45–118 с (стоя на месте), neon 42–133 с (маршрут neon: бег и Neon Dash с поворотами камеры).
- Прогоны с фоном CPU > 10 % переименованы в `_dirty*` и повторены (b2: `neon_orig_1`).
- Столбцы: FPS — средний; 1 % low — FPS; P99 — мс; > 33 / > 50 — кадров дольше 33,3 / 50 мс в минуту; GPU — занятость
  GPU, мс/кадр; CP — время командного процессора, мс/кадр (`tools/r10/ab_sum.py`).

## 5. Стабильность в движении [E]

Прогоны `diag6` (маршрут `mouse`: повороты камеры мышью; захват 60 кадров подряд с 74 с — медленный поворот
`move:60:0`), `SSPC_REFLECTION_QUALITY=original` против `low`. Метрики по нижней половине кадра (дорога, лужи), яркость
0–255, кадр уменьшен в 2 раза:
- **d1** — средняя разница соседних кадров (движение + шум);
- **мерцание** — `|f[t] − (f[t−1] + f[t+1]) / 2|`: плавное движение его почти не даёт, мерцание и «прыжки» дают;
- **горячие пиксели** — доля пикселей с мерцанием > 24/255.

| сцена | уровень | d1 | мерцание (макс.) | горячие пиксели, % (макс.) |
|---|---|---|---|---|
| neon (ночь, дождь, большая лужа) | Исходное | 1,48 | 0,960 (1,925) | 0,161 (0,481) |
| neon | Низкое | 1,46 | 0,947 (1,750) | 0,097 (0,356) |
| user (сумерки, мокрая крыша, вода внизу) | Исходное | 1,06 | 0,776 (2,214) | 0,394 (1,367) |
| user | Низкое | 1,16 | 0,825 (2,004) | 0,436 (1,335) |

- **[E] «Низкое» не добавляет нестабильности.**
  - neon: на «Низком» мерцающих пикселей меньше (0,10 против 0,16 %) — уходит шум трассировки SSR на мокрой
    поверхности. Остальное мерцание — анимация неонового следа и капли дождя, они одинаковы на обоих уровнях.
  - user: разница в пределах разброса прогона. У «Низкого» больше само движение (d1 1,16 против 1,06: камера и
    анимация героя не совпадают кадр в кадр), мерцание растёт вместе с ним. Кадры `diag6/user_road_orig_low_f30.png`
    на глаз одинаковы: вклад SSR в вечернем городе почти не виден.
- **[E] Вид лужи** (`diag6/neon_puddle_orig_low_f30.png`): на «Исходном» тёмная лужа справа от героя глубже и
  зеркальнее; на «Низком» она чуть светлее и матовее. Края луж, сама мокрота, блики фонарей и отражение воды
  остаются (это не SSR).
- **Появление / исчезание отражений:** у SSR отражение пропадает, когда источник уходит за край экрана — это
  свойство «Исходного». На «Низком» экранного отражения нет, поэтому и прыжков от него нет.
- **Переключение на лету** (`diag3`/`diag4`, `ssrcycle`: SSR вкл./выкл. каждую секунду, user и neon стоя): скачка
  на кадре переключения не видно (`diag4/step_17097.png`). Вклад SSR в этих видах слабый, поэтому и переход
  незаметен.
- Кадры `diag5` (neon в беге) не выровнены по времени между уровнями. Для сравнения стабильности они не
  используются: только для вида отражений фонарей на мокрой крыше.

## 6. Применение на лету

- `graphics.reflectionQuality`: `Apply::Live`. Вызов `Reflections::SetQuality`, со следующего кадра игры.
- Зонд на входе `SsrPass` ставится всегда и проверяется по хешу функции. При «Исходном» он только пропускает вызов
  дальше.
- Переключение «Низкое» → «Исходное» начинает SSR с устаревшей историей (`+0x1aed0`). Это тот же случай, что у игры
  при смене `SSR_OPACITY` 0 → > 0. По кадрам `ssrcycle` скачка не видно (§5).
- `SSPC_REFLECTION_QUALITY=original|low` перекрывает настройку (для серий). В журнале — предупреждение.

## 7. Диагностика (только явными переменными, с предупреждением в журнале)

- `SSPC_R12_REFL_STATS=<с>` — вызовы SSR / планарных / воды, значения окружения, классы FX-объектов, уровни целей.
- `SSPC_R12_REFL_DIAG=ssroff,ssrflip,ssrcycle,planaroff,wateroff` — A/B, меняет картинку.
- `SSPC_R12_REFL_HOOK=0` — без зонда: всё как в игре, настройка не действует.

## 8. Тесты

`SSPC_SELFTEST_ONLY=settings SecondSonPC.exe --selftest` (своя LOCALAPPDATA):
- **171 проверка, 0 ошибок**;
- новая группа `Settings.reflections`:
  - пункт есть, Live, Choice в [Graphics];
  - уровни только original / low;
  - по умолчанию original;
  - low применяется на лету, неизвестное значение отклоняется;
  - сохраняется и восстанавливается, сброс раздела возвращает исходное;
- меню «Графика» перечисляет пункт.

## 9. НЕ ПРОВЕРЕНО

- Сцена «фары машин в дождь ночью на дороге» отдельно: neon — дождь ночью с лужами и фонарями, но без трафика.
  Сохранения с ночным дождём и машинами на стенде нет. Инструмент погоды `SSPC_R12_WEATHER` стал годен для замеров
  (a75553e) уже после серии b1; сцена `rainday` (blustery 18:00, дождь, свободный город) серией не проверялась.
- Ручная проверка пункта в меню живьём (с переключением во время игры) — только автотесты и кадры `ssrcycle`.
- GCN-шейдер трассировки SSR (число шагов): дамп `SSPC_DIAG_DUMP_SHADER` с тёплым кэшем ничего не записал. Уровень по
  шагам не вводился (≤ 0,15 мс).
- Бэкенд моста (shadPS4): пункт не зависит от бэкенда (зонд в коде игры), но серии шли только на нативном.
