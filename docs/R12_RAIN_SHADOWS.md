# R12 — тени дождя: что это и пункт «Тени дождя» в «Графике»

Агент **rain**, ветка `feature/r12-rainshadow` (от `feature/r12-integration` 8db0b26), worktree `E:\SecondSonPC-r12-rain`.
Сырые данные: `E:\research\r12\runs\rain\` (`re\` — разбор eboot, остальное — прогоны).
Метки: **[E]** измерено, **[A]** анализ (Ghidra / дизассемблер / байты eboot), **[H]** гипотеза.
Адреса — относительно модуля eboot (`E:\shdps4\CUSA00004\eboot.bin`, смещение в файле = VA + 0x6f30).
Вид результата — **Б** (выигрыш за счёт качества), не ускорение кода.

## 1. Механизм

### 1.1. Три объекта теней [A]

Статическая инициализация 0x4446a0 создаёт три объекта «каскадных теней» по 0x2450 байт (каскады по 0x8e0 байт с
+0, число каскадов +0x2380, вид +0x2440):

| объект | вид (+0x2440) | что рисует | маска геометрии |
|---|---|---|---|
| 0x7d45120 | 0 Directional | тени солнца/луны | — |
| 0x7d47570 | 1 Rain | карта укрытий от дождя: статическая геометрия | 0x10 |
| 0x7d499c0 | 2 Rain Dynamic | то же для движущихся объектов (машины, люди) | 0x1000 |

Карты дождя — **вид сверху строго вниз** (0x600d90 с направлением 0x8000000080000000), каскадов 2 (0xdf9d28), рисуется
только каскад 1 (каскад 0 сразу освобождается — отсюда имена `CSM1_RAIN_SHADOW_*` в таблице параметров рендера
0xd1d7a0..0xd1da40: POLYGON_OFFSET_SLOPE_SCALE, POLYGON_OFFSET, NORMAL_OFFSET, DISTANCE). Дальность
`CSM1_RAIN_SHADOW_DISTANCE` = float 0xdf9d20 = 10000; её сеттер 0x2e3380 просто пишет глобал, читает его только
0x43b7b0 (и геттер 0x2e3390).

### 1.2. Когда они есть [A]

Все функции объекта проверяют одно и то же: для видов 1/2 — итоговая мокрота кадра 0xe87c80 (GetWetness 0x598b50,
аргумент не читает) > 0.

* `IsActive` 0x43b740(объект): вид 1/2 → мокрота > 0; вид 0 → свет солнца 0x1d1dfb8 ≠ 0, интенсивность 0xe87b44 ≠ 0,
  флаг 0x7d45118 = 0.
* `Update` 0x43b7b0(объект, вид) — раз в кадр из 0x41b490 (солнце → дождь → дождь динамический). При мокроте ≤ 0 для
  видов 1/2 — ветка 0x43b90e: каждый каскад с данными рендера освобождается (0x4394a0(0x7d45028, +0x8d0, +0x8d8),
  +0xfc = −1, +0x8d8 = 0, счётчик ссылок +0x8d0 → 0xaa250, +0x8d0 = 0) — и больше ничего. Это собственное состояние
  игры «тени дождя нет».
* 0x43c350 / 0x43fcb0 (из 0x41bb50 / 0x41b8d0) — то же условие, работают только с каскадами, у которых есть данные.

### 1.3. Кто рисует [A+E]

* 0x190330 (из настройки прохода 1, 0x1905e0): если Rain активен — рисует его каскады (0x43c490 / 0x43c780); если нет —
  очищает цель 0xe7d660[чётность кадра]. Затем пишет для частиц текстуру (0x439f60) и параметры каскада
  (0xe7e578 / 0xe7e598..0xe7e5b4, по чётности кадра 0xe86ed0); без каскада — текстура по умолчанию 0x7d4c348 и нули.
* 0x190520 и настройка прохода 28 0x1923f0 — Rain Dynamic, только если `IsActive`.
* [E, wfx 13:20] в user/calm это ~995 depth-only draw/кадр (vs 0x2dfd6af00, ps 0x2dfda9700, глубина 1024², ds
  0x304a20000 / 0x304610000): ~0,15 мс GPU, но ~1,6 мкс CP на draw → почти вся разница CP −1,66 мс «dry против log»
  из ab4 weather. Проход 28 (динамика) — лишь 30–63 из них, остальное — статическая геометрия в проходе 1.

### 1.4. Кто читает [A]

Перебором всех ссылок на объекты 0x7d47570..0x7d4be10:

1. **Проход мокроты 0x597ec0** (тот самый полноэкранный проход в G-буфер, 0,38 мс GPU) — подключает последний
   каскад Rain через 0x43f7c0. Если каскада нет, 0x43f7c0 подключает текстуру по умолчанию 0x7d4c348 и ставит
   сэмплеру `|0x7000` = поле DEPTH_COMPARE_FUNC слова 0 сэмплера GCN = 7 (**ALWAYS**): сравнение глубины всегда
   «проходит» — для мокроты всё открыто небу. То есть карта нужна, чтобы **под укрытием было сухо**.
2. **Частицы** — 0x3ecb20 (константы кадра системы частиц, кадр 0x3ee7d0) копирует параметры каскада Rain из
   0xe7e598..0xe7e5b4 в свой буфер констант (+0x130..+0x148); текстура — 0xe7e578. Что именно с ней делают шейдеры
   частиц (гасят капли под крышей? брызги?) — по коду CPU не видно, смотрим кадрами (§3).
3. Других читателей нет: Rain Dynamic по имени никто не читает, кроме функций отрисовки (общая цель глубины с Rain [H]).

### 1.5. Списки отрисовки карты [A]

* `Update` для каждого каскада с данными рендера (+0x8d8) пишет маску геометрии объекта (0x10 / 0x1000) в каскад +4 и
  через 0x197960 (`mov [rdi+8], esi; ret`) в данные рендера +8 — **каждый кадр** (0x43c04c → 0x43c05e).
* Список отрисовки каскада заводит 0x439650 (задание отбора из 0x43c350) → 0x198d50: маска списка = данные рендера +8
  `& 0x31ff`; в список попадают только объекты этой маски.
* Другие вызовы 0x197960: внутри 0x438f80 (выделение каскада, из того же Update — до записи маски), 0x439486 (новые
  данные рендера, маска 2), 0x43800f (сеттер каскада 0x438000; прямых вызовов нет), 0x3be8d6 / 0x596776 (не тени дождя).

## 2. Как выключить

### 2.1. Отвергнуто: путь игры «мокрота 0» только для объектов дождя [E]

Первый вариант повторял то, что игра делает сама в сухую погоду: `IsActive` 0x43b740 заменён реконструкцией (для
видов 1/2 — «нет»), `Update` для них выполняет ветку 0x43b90e (каскады освобождаются). Он работает как задумано
(f1, rainday calm, n=1, не замер: IsActive дождя 0 «да» / ~220 «нет» за 5 с, каскадов нет, draw/кадр 4733 → 3541,
CP 17,8 → 15,5 мс, FPS 45,4 → 45,8), **но ломает кадр целиком**: всё обесцвечено, пропали туман и дымка, другая
экспозиция — `E:esearch12unsain1ainday_calm_offrameslip_014307.png` против
`f1ainday_calm_origrameslip_014410.png`. Сухая погода (weather `dry`) так не выглядит, значит виновата не
«сухость», а сочетание «мокрота > 0, карты нет»: проход мокроты тогда берёт запасной путь 0x43f7c0 (текстура по
умолчанию 0x7d4c348 + сравнение глубины ALWAYS), которым игра при дожде никогда не пользуется; на этом эмуляторе он
даёт мусор на весь экран [H — механизм искажения не разобран]. Оставлено только как диагностика
`SSPC_R12_RAIN_DIAG=release` («Эксперименты» → «Инструменты стенда (R12)»), в пункт настроек не идёт.

### 2.2. Пункт «Тени дождя: выключены» = пустая карта [A]

* `Update` 0x43b7b0 — проба на входе (пролог 20 байт, без RIP-относительных операндов и ветвлений). Оригинал
  выполняется всегда; при «Выключены» сразу после него для объектов дождя маска данных рендера каждого каскада = 0.
  Список отрисовки (0x198d50) тогда не берёт ни одного объекта: в карту ничего не рисуется.
* Карта при этом остаётся настоящей: каскад выделен, цель глубины очищается игрой каждый кадр (0x439ab0), проход
  мокроты и частицы получают её как обычно — запасной путь 2.1 не используется. Смысл — «ничто не укрыто от дождя».
* `IsActive` не трогается. Переключение на лету: желаемое состояние фиксируется в начале кадра (обновление солнца —
  первое в 0x41b490); при «Исходные» `Update` сам ставит маску обратно в следующем кадре.
* Закреплены хешами (иначе ничего не ставится): 0x43b7b0, 0x598b50, 0x190330, 0x597ec0, 0x43f7c0, 0x4394a0, 0xaa250,
  0x197960, 0x198d50 (+ 0x43b740 для диагностики `release`).

Ничего не возвращает «заглушку» и не пропускает чужие draw: все проходы игры идут как есть, пустеет только список
объектов двух карт дождя, которые кроме мокроты и частиц никто не читает.

## 3. Пункт настроек

* «Настройки» → «Графика» → **«Тени дождя»** (`[Graphics] rainShadows` в settings.toml): «Исходные» (`original`, по
  умолчанию — как в игре) / «Выключены (ничто не укрыто от дождя)» (`off`). Применяется сразу, без перезапуска.
  `SSPC_RAIN_SHADOWS=original|off` перекрывает пункт (тогда изменения в меню не применяются — пишется в журнал).
* Что меняется при «Выключены» [A, на кадрах ещё не проверено]: земля под мостами, навесами, крышами и в
  проездах мокнет так же, как открытая улица (лужи/блеск мокрого асфальта под укрытием). Дождь, туман, лужи на
  открытом месте и отражения — без изменений; в сухую погоду пункт ничего не меняет (карт нет).
* Цена [E — только у отвергнутого варианта 2.1, f1, n=1]: в rainday −1192 draw/кадр, CP 17,8 → 15,5 мс; у пустой
  карты ожидается почти то же (остаются очистка и привязка двух целей) — замер после финала.
* Журнал: при установке `Rain shadows: Update 0x43b7b0 probed - original|off (empty map)`; при переключении
  `Rain shadows: off|original (from the game's next frame)`; если хеши не совпали — `hooks not installed` (пункт
  ничего не делает, игра как есть).
* Самотест настроек: `Settings.rainShadows` — 6 проверок (значения, по умолчанию, сохранение в [Graphics], меню).

## 4. Что не проверено

Сборка с пустой картой не запускалась (финал координатора на стенде, владелец тестирует сам): кадры «до/после»
(rainday день, user сумерки, Neon ночь — под мостом/навесом/в помещении), число draw, A/B FPS/1% low/P99/CP/GPU,
переключение на лету в движении (`SSPC_R12_RAIN_CYCLE=10`), промежуточный уровень по дальности
(`SSPC_R12_RAIN_DIST`) — всё после освобождения стенда.
