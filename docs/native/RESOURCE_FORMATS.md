# Форматы ресурсов inFAMOUS Second Son (то, что подтверждено)

Метки: **[П]** — подтверждено на реальных файлах и/или в коде загрузчика eboot; **[Г]** — гипотеза; **[?]** — неизвестно.
Образцы: `E:\shdps4\CUSA00004\art\cache\*.xpps` (1 621 пакет, 21,3 ГиБ). Код: `native/engine/resources/`.
Исследовательские скрипты: `native/tools/research/kcap*.py`.

## 1. Пакет KCAP (.xpps)

Пакет — **перемещаемый снимок памяти**: заголовок с таблицами, затем область данных (все сегменты подряд).
Указатели внутри данных хранятся как u32-смещения от начала области данных и правятся при загрузке по
служебному потоку. Ничего не сжато.

### 1.1 Заголовок [П]

| Смещение | Тип | Поле |
|---|---|---|
| +0x00 | char[4] | `KCAP` |
| +0x04 | u16 | версия = 13 (единственная встреченная) |
| +0x06 | u16 | вид пакета (3 мир, 4 чанк мира, 0xA миссия, 0xD hires, 0xE персонаж, 0xF катсцена …) [Г: назначение] |
| +0x08…+0x14 | u32 ×4 | [?] (`0x18f`, `0x2b5d0000`, …; +0x14: 1/2/0x401) |
| +0x18 | u32 | начало области таблиц = 0x98 (всегда) |
| +0x1C | u32 | размер области таблиц; **размер заголовка = +0x18 + +0x1C** |
| +0x28 | u32 | размер заголовка (данные начинаются здесь); 0 у пустых пакетов |
| +0x2C | u32 | размер данных; заголовок + данные = размер файла |
| +0x78 | u8[16] | хеш пакета (используется как «версия источника» в кэше `.spcmesh`) |
| +0xA0 | u64 | число сегментов |
| +0xB0 | u64 | число блоков |
| +0xC0 | u64 | 0/1 [?] |
| +0xC8 | — | таблица сегментов, за ней **сразу** таблица блоков |

Пустые пакеты (28 файлов `*.hires.xpps` по 200 байт): размер заголовка 0, сегментов/блоков 0.

### 1.2 Сегмент (0x28 байт) [П]

`{u8 флаги, u8 0xFF, u16 пул, u32 размер, u64 смещение, u64 база (0 в файле, адрес после загрузки — загрузчик
`0x5ee750` читает +0x10), u64 первый блок (в рантайме — указатель на блоки), u64 число блоков}`.
Пул 0 — память CPU (флаги 0x01/0x03), пул 1 — память GPU (флаги 0x12/0x13), пул 2 — служебный поток (0x03).

### 1.3 Блок (12 байт) [П]

`{u32 размер, u32 смещение, u16 выравнивание, u16 тип}` — по коду загрузчика `0x30fc00` (смещение по +4, тип —
байт +10). Ранее в документах эталона раскладка была сдвинута на 8 байт.

| Тип | Пул | Роль |
|---|---|---|
| 2 | 2 | поток чанков (служебный) [П] |
| 6 | 0 | особый блок, его адрес загрузчик сохраняет в `+0x90` [П]; по смыслу — корень/каталог [Г] |
| 9 | 1 | **резерв при загрузке**: в файле данных нет, лежит сразу за сохранёнными данными GPU-сегмента, может выходить за конец файла [П по 250+2 пакетам] |
| 18 | 1 | данные GPU (вершины, индексы, текстуры) [П] |
| 1, 3, 11, 14, 16, 24 … | 0 | объекты CPU [?: тип ↔ класс не разобран] |

### 1.4 Служебный поток [П] (eboot `0x30a310`)

В каждом блоке типа 2: последовательность чанков `{u32 тег, u32 размер, данные}`; теги — ASCII задом наперёд:

| Тег | Обработчик | Содержимое |
|---|---|---|
| ` DIC` | `0x30a310` | `{u32 n, u32 0, n × {u32 место, u32 0, u64 хеш типа}}` → в место пишется индекс типа (`0x2a6e40`: бинарный поиск в таблице 7 084 типов `0xa5ff70`) |
| `KNLI` | `0x30a4a0` | внутренние ссылки, см. 1.5 |
| `KNLX` | `0x30a700` | внешние ссылки (на другие пакеты), записи по 0x18 байт [Г: имя/хеш + смещение] |
| `PYTO` | `0x30a910` | `n × {u32 место, u8 ширина, u8 флаг 0x8000, u8 вид 0/1/2 → |0x1000/0x2000, u8, u64 хеш типа}` |
| `PLPS` | `0x30b1c0` | правки свойств по рефлексии (`0x4cfcb0`: таблица полей `0xd057a0`) [?] |
| ` DNE` | — | конец |

### 1.5 Ссылки KNLI [П]

`{u32 n, n × {u32 вид, i32 длина_в_u16}, потоки u16}`. Декодер (`0x5d2260`): база = −1, последнее = −1;
код ≥ 0 → `последнее = код·4 + база`; код < 0 без бита 0x4000 → серия: `последнее += 4` и ещё `(код & 0x3FFF) − 1`
раз; код с битом 0x4000 → `база = (код & 0x3FFF) << 17`. Значение по месту ссылки — u32 смещение цели.

| Вид | Запись после загрузки |
|---|---|
| 0, 3 | 64-битный указатель |
| 1 | база T# (`адрес >> 8`, `0x63ab20`) |
| 2 | база V# (48 бит: dword0 + младшие 12 бит dword1) |
| 4 | u32 = `адрес >> 8` |

Проверка: `hero.xpps` — 8 720 ссылок (0: 7 582, 2: 480, 3: 195, 4: 463), невалидных 0.

## 2. Геометрия [П]

Найдена по DrawSingle `0x1a1960` и подтверждена на 41 части Делсина (`hero.xpps`) и 12 428 записях во всех
разобранных пакетах (0 ошибок декодирования).

| Смещение | Поле |
|---|---|
| +0x00 | u8[16] id (первые 8 байт встречаются в таблице вариантов модели) |
| +0x10 | указатель (описание/владелец) [?] |
| +0x18 | u64: биты 0–15 число треугольников, 16–31 маска видов (0x4001 служебные боксы, 0x600B/0x6003/0x4003 основной вид), 48–55 s8 LOD мин., 56–63 s8 LOD макс. (пороги — таблица `0xdfaa30`, выбор в `0x1ec170`) |
| +0x20 | f32[3] AABB min, +0x2C f32[3] AABB max |
| +0x38 | f32 (0,67 у всех частей героя) [?] |
| +0x40, +0x44 | f32 (≈102) [?] |
| +0x58 | указатель (KNLI вид 3) на индексы: u16, список треугольников |
| +0x60 | указатель на массив V# (16 байт на поток), массив лежит сразу за записью (+0x80) |
| +0x68 | u32 число индексов |
| +0x6C | u8 число потоков (байт повторён 4 раза) |

V#: dword0 база, dword1 `stride` в битах 16–29, dword2 число записей, dword3 `dst_sel` 0–11, `nfmt` 12–14, `dfmt` 15–18.

Потоки скиннингового меша героя (stride 20 + 8 + 8):

| Поток | Формат | Смысл |
|---|---|---|
| 0 | 16_16_16_16 snorm (V# говорит SNORM_OGL) | позиция: **raw/32767**, AABB = raw/32767 до последней цифры (квантование floor(x·32767)) [П] |
| 1 | 16 float по +6 | 4-я компонента позиции как half [?] |
| 2 | 16_16_16_16 sint по +8 | индексы костей [Г] |
| 3 | 8_8_8_8 unorm по +16 | веса костей [Г] |
| 4 | 2_10_10_10 snorm | нормаль: **X в младших битах** [П: |cos(грань, нормаль)| = 0,976] |
| 5 | 2_10_10_10 snorm по +4 | тангенс [Г] |
| 6 | 16_16 float | UV0 [Г] |
| 7 | 8_8_8_8 unorm по +4 | цвет/второй набор [?] |

Пространство модели нормировано: весь персонаж занимает z ∈ [−1, 1] (Z вверх, лицом к +X). Обход треугольников —
против часовой стрелки снаружи (100 % треугольников) [П].

Корень пакета персонажа (смещение 0): `+0x58` указатель на список геометрий модели, `+0x60` их число (41) [П для
`hero.xpps`]. Описание модели (`0x2b0…`): пары {указатель, число}: флаги частей `0xb90`×41 (8 байт, биты 0–1 —
режим `0x1ec170`), список геометрий `0xd70`×41, таблица вариантов `0xad0`×12 (id геометрии → дескриптор) [Г].

### 2.1 Деквантование позиций [П]

`+0x38/+0x3C/+0x40` — f32×3 смещение, `+0x44` — f32 масштаб: **сантиметры = смещение + масштаб · snorm**.
Делсин: смещение (0,67; 0; 102,185), масштаб 102,485 → ступни ≈ 0 см, макушка без маски ≈ 183 см. Нативный
движок хранит метры (см/100), начало модели — у ступней.

## 2a. Чанки мира (a#/b#/c#/d#.xpps, вид 4) [П на a1.xpps]

Корневой каталог — блок типа 6: `{u32 n, u32 n, указатель, n указателей на объекты}`. Объект сцены чанка:

| Поле | Содержимое |
|---|---|
| +0xA8 / +0xB0 | экземпляры ×N, 8 байт: `u16 вид (0 — основной набор; 2/4/6 [?]), u16 индекс матрицы, u16 (слот геометрии << 2 \| режим), u16 [?]` |
| +0xB8 / +0xC0 | матрицы ×M, 48 байт: 3×4 построчно, перенос (см) — 4-й элемент каждой строки; базис = поворот × масштаб |
| +0xC8 / +0xD0 | слоты геометрии ×K: указатели на записи геометрии; **null — геометрия из другого пакета** (KNLX), не разобрано |

a1.xpps: 3 788 экземпляров, 1 432 матрицы, 238 слотов; 1 492 экземпляра основного набора со своей геометрией,
2 202 — с внешней. Мир: Z вверх, сантиметры. Проверено визуально (хвойный лес, скалы) и в нативном рендере.

## 2b. Текстуры [П]

* Объект текстуры (блок 0x60): `+0x28` T# (8 dword), `+0x48` u64 id. dword0 T# — ссылка KNLI **вида 4** (`адрес >> 8`)
  на данные в GPU-сегменте (не вида 1).
* T#: dw1 формат данных [25:20] (35–41 = BC1–BC7, 10 = 8_8_8_8), формат чисел [29:26]; dw2 ширина−1 [13:0],
  высота−1 [27:14]; dw3 dst_sel [11:0], уровни [15:12]/[19:16], тайлинг [24:20], тип [31:28] (8 — 1D, 9 — 2D);
  dw4 pitch−1 [26:13].
* У всех текстур героя и a1 — **тайлинг 13 (thin 1D)**: элементы (BC-блоки 4×4) в микротайлах 8×8 в порядке
  Мортона (x0 y0 x1 y1 x2 y2), тайлы построчно; mip-уровни подряд, каждый выровнен до целых тайлов (у 70 из 80
  текстур героя конец цепочки совпадает с началом следующей текстуры). Проверено декодированием в PNG
  (рубашка в клетку, нашивка «128 SEATTLE»).
* Экземпляр материала (геометрия `+0x10`): `+0x18` хеш, `+0x20` → общий шаблон, `+0x28` → V#, `+0x30` → привязки
  текстур ×`+0x38`; привязка 0x30 байт: `+0x00` u64 id текстуры, `+0x10` указатель обратно на материал,
  `+0x18` u64 **категория** (1 — цветовая карта, ровно одна; 3 — BC5 нормали, может повторяться; 4 — BC4 [?]).
* Текстура по id может лежать в другом пакете: у героя 6 цветовых карт вне `hero.xpps` (1 в
  `hero.flavor(default).xpps`, 3 в `core_common.sprig.xpps`, 2 не найдены).

## 3. Нативный формат .spcmesh (v2) [реализовано]

Little-endian. Заголовок 64 байта: `SPCM`, u16 версия 1, u16 маркер порядка байт 0xFEFF, размер заголовка,
флаги, число мешей, смещение таблицы, размер записи (96), CRC-32 всего после заголовка, u64 размер файла,
хеш исходного KCAP. Запись меша 96 байт: id, смещение в источнике, числа вершин/индексов, флаги вершин
(позиция/нормаль/UV0), шаг, смещения данных (u64), AABB, маска видов. Вершины f32, индексы u32.
Читатель проверяет каждое поле, переполнения, границы, индексы и CRC (`tests/test_geometry.cpp`).

## 5. Анимация [П] (N11; код `resources/anim_clip.*`, eboot `0x71d50`, `0x887e60` и декодеры дорожек)

**Скелет `'60SE'`** (hero.xpps +0xf80): `+0x04` размер объекта, `+0x10` u16 число суставов (653), `+0x18`
самоотносительное смещение локальной позы покоя: N × 0x30 {кватернион xyzw, перенос xyz (см) + 1, масштаб xyz + 1};
`+0x40` N × {u16 индекс, u16 флаг}; прочие таблицы (u32 хеши имён). Поза покоя, собранная по родителям
рендер-скелета, совпадает с bind-матрицами (ошибка 4,8e-7 м). Сустав 5 — листовой хелпер с масштабом
(20, 30, 53,6). Суставы 413–652: родитель 0, привязка в нуле (ткань).

**Клип `'70AE'`** (блоки типа 0; 16-байтное выравнивание):
| Смещение | Поле |
|---|---|
| +0x04 / +0x08 | f32 длительность в кадрах, f32 1,0 |
| +0x0C / +0x0E | u16 размер заголовка-до-данных, u16 число суставов целевого рига (Делсин 413) |
| +0x10 / +0x12 | u16 число кадров (ключей), u16 число сегментов |
| +0x16…+0x24 | u16 ×8: константные rot / trans / scale / float, анимированные rot / trans / scale / float |
| +0x28 / +0x30 | u16 число масок суставов / смещение масок |
| +0x2C | u32 флаги: бит k = дорожки вида k в формате переменной разрядности |
| +0x38 / +0x3C | смещения таблиц сегментов {u32, u32 смещение в клипе} и кадров {u16 начало, u16 длина} |
| +0x40…+0x4C | константные данные rot / trans / scale / float |
| +0x50 | слова формата: для каждого вида с флагом {константное слово, слово на каждую анимированную дорожку} |
| +0x60 | списки суставов u16 (константные rot — выравнивание до 8, остальные — до 4) |
Смещения +0x30…+0x50 — **самоотносительные** (цель = поле + значение).

Форматы значений: 48-битный кватернион (BE16 A, BE32 = B:15 C:15 idx:2; масштаб √2/32767, сдвиг −0,7071, W
восстанавливается, idx — номер отброшенной компоненты); 3 × f32 (константный перенос/масштаб); переменная
разрядность: слово формата {mantissa:5, exponent:4, sign:1} × 3 c бита 2 + idx:2, компоненты в потоке в порядке
2, 1, 0, каждая — знак, экспонента, мантисса MSB-first; exponent = 0 → дополнительный код × 1/(2^m − 1), иначе
float с экспонентой raw + 128 − 2^(e−1).

Сегмент: заголовок 8 × u32 (размеры info rot/trans/scale/float и ключей rot/trans/scale/float), info (значение на
кадре 0 каждой дорожки), битовая маска ключей ((rot+trans+scale+float) × len бит, бит j = кадр j+1), ключи (по
дорожкам подряд), значение после последнего кадра — info следующего сегмента. Интерполяция slerp/lerp между
соседними ключами, вес = (local + frac − prev) / (next − prev). Кадр = (кадры − 1) × фаза, 30 к/с.

## 6. Коллизия Havok [П] (N11; код `resources/havok.*`)
Packfile Havok `hk_2013.2.0-r1` (магия `57E0E057 10C0C010`, правила 8/1/1/1, секции по 0x40: `__classnames__`,
`__types__` (пусто), `__data__`; локальные {src, dst}, глобальные {src, секция, dst}, виртуальные {объект, секция
имён, смещение имени} фиксапы). Объекты чанков: `hknpStaticCompoundShape` (+0x60 экземпляры по 0x80: столбцы
поворота +0x00/+0x10/+0x20, перенос +0x30, масштаб +0x40, указатель формы +0x50), `hknpCompressedMeshShape`
(+0xA0/+0xB0 домен, +0xD0 секции по 0x60 {+0x30 codec: смещение и масштаб, +0x48 первая упакованная вершина,
+0x4C (первый общий индекс << 8) | число упакованных, +0x50 (первый примитив << 8) | число, +0x59 число общих},
+0xE0 примитивы 4 × u8 (c = d — треугольник, `DE AD DE AD` — удалён), +0xF0 индексы общих вершин u16, +0x100
упакованные вершины u32 11/11/10, +0x110 общие вершины u64 21/21/22 в домене). Метры, Z вверх, та же мировая
система, что у чанков. a1: 19 сеток, 27 361 треугольник — скалы, стволы, постройки; грунта нет.
