# Форматы ресурсов inFAMOUS Second Son (то, что подтверждено)

Метки: **[П]** — подтверждено на реальных файлах и/или в коде загрузчика eboot; **[Г]** — гипотеза; **[?]** — неизвестно.
Образцы: `E:\shdps4\CUSA00004\art\cache\*.xpps` (1 621 пакет, 21,3 ГиБ). Код: `native/engine/resources/`.
Исследовательские скрипты: `native/tools/research/kcap*.py`.

## 1. Пакет KCAP (.xpps)

Пакет — **перемещаемый снимок памяти**: заголовок с таблицами, затем область данных (все сегменты подряд).
Указатели внутри данных хранятся как u32-смещения от начала области данных и правятся при загрузке по
служебному потоку. Ничего не сжато.

### 1.1 Заголовок [П]

| Смещение | Тип | Поле |
|---|---|---|
| +0x00 | char[4] | `KCAP` |
| +0x04 | u16 | версия = 13 (единственная встреченная) |
| +0x06 | u16 | вид пакета (3 мир, 4 чанк мира, 0xA миссия, 0xD hires, 0xE персонаж, 0xF катсцена …) [Г: назначение] |
| +0x08…+0x14 | u32 ×4 | [?] (`0x18f`, `0x2b5d0000`, …; +0x14: 1/2/0x401) |
| +0x18 | u32 | начало области таблиц = 0x98 (всегда) |
| +0x1C | u32 | размер области таблиц; **размер заголовка = +0x18 + +0x1C** |
| +0x28 | u32 | размер заголовка (данные начинаются здесь); 0 у пустых пакетов |
| +0x2C | u32 | размер данных; заголовок + данные = размер файла |
| +0x78 | u8[16] | хеш пакета (используется как «версия источника» в кэше `.spcmesh`) |
| +0xA0 | u64 | число сегментов |
| +0xB0 | u64 | число блоков |
| +0xC0 | u64 | 0/1 [?] |
| +0xC8 | — | таблица сегментов, за ней **сразу** таблица блоков |

Пустые пакеты (28 файлов `*.hires.xpps` по 200 байт): размер заголовка 0, сегментов/блоков 0.

### 1.2 Сегмент (0x28 байт) [П]

`{u8 флаги, u8 0xFF, u16 пул, u32 размер, u64 смещение, u64 база (0 в файле, адрес после загрузки — загрузчик
`0x5ee750` читает +0x10), u64 первый блок (в рантайме — указатель на блоки), u64 число блоков}`.
Пул 0 — память CPU (флаги 0x01/0x03), пул 1 — память GPU (флаги 0x12/0x13), пул 2 — служебный поток (0x03).

### 1.3 Блок (12 байт) [П]

`{u32 размер, u32 смещение, u16 выравнивание, u16 тип}` — по коду загрузчика `0x30fc00` (смещение по +4, тип —
байт +10). Ранее в документах эталона раскладка была сдвинута на 8 байт.

| Тип | Пул | Роль |
|---|---|---|
| 2 | 2 | поток чанков (служебный) [П] |
| 6 | 0 | особый блок, его адрес загрузчик сохраняет в `+0x90` [П]; по смыслу — корень/каталог [Г] |
| 9 | 1 | **резерв при загрузке**: в файле данных нет, лежит сразу за сохранёнными данными GPU-сегмента, может выходить за конец файла [П по 250+2 пакетам] |
| 18 | 1 | данные GPU (вершины, индексы, текстуры) [П] |
| 1, 3, 11, 14, 16, 24 … | 0 | объекты CPU [?: тип ↔ класс не разобран] |

### 1.4 Служебный поток [П] (eboot `0x30a310`)

В каждом блоке типа 2: последовательность чанков `{u32 тег, u32 размер, данные}`; теги — ASCII задом наперёд:

| Тег | Обработчик | Содержимое |
|---|---|---|
| ` DIC` | `0x30a310` | `{u32 n, u32 0, n × {u32 место, u32 0, u64 хеш типа}}` → в место пишется индекс типа (`0x2a6e40`: бинарный поиск в таблице 7 084 типов `0xa5ff70`) |
| `KNLI` | `0x30a4a0` | внутренние ссылки, см. 1.5 |
| `KNLX` | `0x30a700` | внешние ссылки (на другие пакеты), записи по 0x18 байт [Г: имя/хеш + смещение] |
| `PYTO` | `0x30a910` | `n × {u32 место, u8 ширина, u8 флаг 0x8000, u8 вид 0/1/2 → |0x1000/0x2000, u8, u64 хеш типа}` |
| `PLPS` | `0x30b1c0` | правки свойств по рефлексии (`0x4cfcb0`: таблица полей `0xd057a0`) [?] |
| ` DNE` | — | конец |

### 1.5 Ссылки KNLI [П]

`{u32 n, n × {u32 вид, i32 длина_в_u16}, потоки u16}`. Декодер (`0x5d2260`): база = −1, последнее = −1;
код ≥ 0 → `последнее = код·4 + база`; код < 0 без бита 0x4000 → серия: `последнее += 4` и ещё `(код & 0x3FFF) − 1`
раз; код с битом 0x4000 → `база = (код & 0x3FFF) << 17`. Значение по месту ссылки — u32 смещение цели.

| Вид | Запись после загрузки |
|---|---|
| 0, 3 | 64-битный указатель |
| 1 | база T# (`адрес >> 8`, `0x63ab20`) |
| 2 | база V# (48 бит: dword0 + младшие 12 бит dword1) |
| 4 | u32 = `адрес >> 8` |

Проверка: `hero.xpps` — 8 720 ссылок (0: 7 582, 2: 480, 3: 195, 4: 463), невалидных 0.

## 2. Геометрия [П]

Найдена по DrawSingle `0x1a1960` и подтверждена на 41 части Делсина (`hero.xpps`) и 12 428 записях во всех
разобранных пакетах (0 ошибок декодирования).

| Смещение | Поле |
|---|---|
| +0x00 | u8[16] id (первые 8 байт встречаются в таблице вариантов модели) |
| +0x10 | указатель (описание/владелец) [?] |
| +0x18 | u64: биты 0–15 число треугольников, 16–31 маска видов (0x4001 служебные боксы, 0x600B/0x6003/0x4003 основной вид), 48–55 s8 LOD мин., 56–63 s8 LOD макс. (пороги — таблица `0xdfaa30`, выбор в `0x1ec170`) |
| +0x20 | f32[3] AABB min, +0x2C f32[3] AABB max |
| +0x38 | f32 (0,67 у всех частей героя) [?] |
| +0x40, +0x44 | f32 (≈102) [?] |
| +0x58 | указатель (KNLI вид 3) на индексы: u16, список треугольников |
| +0x60 | указатель на массив V# (16 байт на поток), массив лежит сразу за записью (+0x80) |
| +0x68 | u32 число индексов |
| +0x6C | u8 число потоков (байт повторён 4 раза) |

V#: dword0 база, dword1 `stride` в битах 16–29, dword2 число записей, dword3 `dst_sel` 0–11, `nfmt` 12–14, `dfmt` 15–18.

Потоки скиннингового меша героя (stride 20 + 8 + 8):

| Поток | Формат | Смысл |
|---|---|---|
| 0 | 16_16_16_16 snorm (V# говорит SNORM_OGL) | позиция: **raw/32767**, AABB = raw/32767 до последней цифры (квантование floor(x·32767)) [П] |
| 1 | 16 float по +6 | 4-я компонента позиции как half [?] |
| 2 | 16_16_16_16 sint по +8 | индексы костей [Г] |
| 3 | 8_8_8_8 unorm по +16 | веса костей [Г] |
| 4 | 2_10_10_10 snorm | нормаль: **X в младших битах** [П: |cos(грань, нормаль)| = 0,976] |
| 5 | 2_10_10_10 snorm по +4 | тангенс [Г] |
| 6 | 16_16 float | UV0 [Г] |
| 7 | 8_8_8_8 unorm по +4 | цвет/второй набор [?] |

Пространство модели нормировано: весь персонаж занимает z ∈ [−1, 1] (Z вверх, лицом к +X). Обход треугольников —
против часовой стрелки снаружи (100 % треугольников) [П].

Корень пакета персонажа (смещение 0): `+0x58` указатель на список геометрий модели, `+0x60` их число (41) [П для
`hero.xpps`]. Описание модели (`0x2b0…`): пары {указатель, число}: флаги частей `0xb90`×41 (8 байт, биты 0–1 —
режим `0x1ec170`), список геометрий `0xd70`×41, таблица вариантов `0xad0`×12 (id геометрии → дескриптор) [Г].

## 3. Нативный формат .spcmesh (v1) [реализовано]

Little-endian. Заголовок 64 байта: `SPCM`, u16 версия 1, u16 маркер порядка байт 0xFEFF, размер заголовка,
флаги, число мешей, смещение таблицы, размер записи (96), CRC-32 всего после заголовка, u64 размер файла,
хеш исходного KCAP. Запись меша 96 байт: id, смещение в источнике, числа вершин/индексов, флаги вершин
(позиция/нормаль/UV0), шаг, смещения данных (u64), AABB, маска видов. Вершины f32, индексы u32.
Читатель проверяет каждое поле, переполнения, границы, индексы и CRC (`tests/test_geometry.cpp`).

## 4. Не разобрано

Текстуры (T# известен, тайлинг/форматы BC не проверены), материалы, скелет и анимации (в eboot есть Havok:
`hkaSkeleton`/`hkx*` и свой `CsMesh: Skin`), сцены мира и расстановка объектов, коллизии (Havok `hkcd*`),
частицы, звук (`.psarc` Wwise), видео (`.bsf`).
