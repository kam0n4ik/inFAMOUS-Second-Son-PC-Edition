# R12 — погода движка и инструмент стенда воспроизводимых погодных состояний

Агент **weather**, ветка `feature/r12-weather` (от `3dd34db`), worktree `E:\SecondSonPC-r10-cp`.
Сырые данные: `E:\research\r12\runs\weather\` (`re\` — разбор eboot, `f1\` — проверки инструмента,
`survey\` — какое время суток грузит каждое сохранение).
Метки: **[E]** измерено, **[A]** анализ (Ghidra/дизассемблер/данные eboot), **[H]** гипотеза.
Адреса — относительно модуля eboot (`E:\shdps4\CUSA00004\eboot.bin`, смещение в файле = VA + 0x6f30).

## 1. Что есть в движке

### 1.1. Погода = объект времени суток (TOD)

* [A] Вся «погода» города — это объекты **CTimeOfDayParams** (`TIME_OF_DAY_PARAMS`), таблица рефлексии
  0xd1bc60..0xd1e2a0 (строки по 0x60 байт: хеш имени `h*101+lower(c)`, тип, смещение поля, сеттер; дамп
  `re\env_table.txt`). Отдельной системы «дождь вкл/выкл» с интенсивностью в eboot нет.
* [A] Менеджер TOD — 0x7f8e800: +0 текущий объект, +8 «ensured time of day» (пустой по умолчанию, 0x59d700),
  +0x10 запрошенный id, +0x18 случайный id (0x59cca0, rand() среди TOD с флагом +0x51), +0x20 id-override (−1 при
  загрузке), +0x28 часы (доля суток), +0x30/+0x38/+0x40 хеш-таблица зарегистрированных TOD
  (узел: u32 хеш, u64 id @+8, объект @+0x10, next @+0x18).
* [A] Обновление 0x59cf80 — раз в кадр из главного цикла 0x29c8d0, до блендинга параметров рендера 0x1ba7c0. На
  запрошенный TOD переключается только когда загружен пакет `"<мир>_x_<tod>"` (реестр пакетов 0x7d37610).
* [E] В городе (world_seaport) зарегистрировано 8 объектов (журнал `f1\wet_user\weather.log`):

  | TOD | id | WEATHER_KIND | WETNESS / PUDDLE | часы | флаги |
  |---|---|---|---|---|---|
  | time_of_day_sunset_candy | 0xaf84cc946e3c9dd3 | Default | 0,80 / 0,70 | 17:10 | random |
  | time_of_day_hazy_sunset | 0xe619cd89b5fd4fc4 | Default | 0,70 / 0,80 | 17:00 | random |
  | time_of_day_blustery | 0x8136092ea1a1ce51 | **Rainy** | 0,90 / 1,00 | 18:00 | random |
  | time_of_day_hdr_night | 0xfb35635fdfb25c8e | **Rainy** | 0,90 / 1,00 | 00:00 | random |
  | time_of_day_dismal | 0x687c4dc40dc9119d | Default | 0,88 / 0,90 | 17:00 | **default**, random |
  | time_of_day_early_morning | 0x64fc3cd2b02ef099 | Default | 0,70 / 0,80 | 06:00 | — |
  | time_of_day_prototype_001 | 0xf6cb4dc47cb7b579 | Default | 0,70 / 0,80 | 10:00 | random |
  | ensured time of day | 0xf88edfc3ba055dc5 | Default | 0 / 0 | — | (заглушка загрузки) |

  Деревня (пролог, ранние сохранения): time_of_day_sunbreak, Default, 17:00, WETNESS 0,5 / PUDDLE 0,8 [E].

  Пакеты освещения у каждого свои, ~500 МБ (`art\cache\imposter-/sh-/spec-world_seaport(<tod>).xpps`) [A]; в реестре
  пакетов зарегистрированы все семь [E].
* [E] **Сухого TOD в городе нет**: даже у «солнечных» WETNESS_LEVEL 0,7–0,88. Поэтому проход мокроты идёт каждый
  кадр в любой погоде (счётчик пробы: 81–95 вызовов на 81–95 кадров).

  (GetWetness 0x598b50).
* [A] При итоговой мокроте > 0: проход мокроты 0x597ec0 (ворота 0x190c90) и карты теней дождя (виды теней

### 1.3. Независимые и связанные параметры

* **Связано с загрузкой мира / миссией** [A]: сам выбор TOD (а с ним небо, освещение, пакеты, WEATHER_KIND, часы,
  частицы дождя). 0x50bda0 при загрузке мира выбирает id: TOD миссии (0x590400/0x532300 по таблице 0x7f77a80),
  иначе override 0x7f8e820, иначе TOD прогресса сюжета (0x52f520/0x532300), иначе сохранённый world+0x390,
  иначе TOD с флагом default (dismal). Результат — в stream request +0x68 (0x46f670), скриптовое свойство `TODP`
  (сеттер 0x2e2480). На лету TOD не меняется → **день/ночь/дождь = разные сохранения**.
* **Независимо, на лету** [A+E]: WETNESS_LEVEL и PUDDLE_LEVEL текущего TOD — данные, которые блендинг читает каждый
  кадр; запись подхватывается на следующем кадре [E]. Остальные поля §1.2 тоже читаются каждый кадр [A], но
  инструмент их не пишет (не проверено, что безопасно).
* **Связано с переходами** [A]: оверрайды (зоны/скрипты) могут подмешивать свою мокроту; флаги перехода TOD
  0x7e00740 | 0x7dff388 (0x59d560).

## 2. Инструмент `SSPC_R12_WEATHER` (коммиты 11bdaa2 — инструмент, a75553e — цена на кадре, откат на выходе)

`src/engine/render/weather.{h,cpp}`, подключение — `src/bridge/shadps4/bootstrap.cpp`. Только диагностика: без флага
ничего не ставится.

| переменная | значение |
|---|---|
| `SSPC_R12_WEATHER=log` | только журнал |
| `SSPC_R12_WEATHER=dry` | WETNESS_LEVEL текущего TOD = 0 |
| `SSPC_R12_WEATHER=wet[:<w>[:<p>]]` | WETNESS_LEVEL = w (по умолчанию 1), PUDDLE_LEVEL = p (по умолчанию не трогается); 0 ≤ w, p ≤ 4 |
| `SSPC_R12_WEATHER_AT=<s>` | применять не раньше <s> c от старта процесса (по умолчанию — как только безопасно) |
| `SSPC_R12_WEATHER_UNTIL=<s>` | на <s> c вернуть исходные значения (по умолчанию — на выходе) |
| `SSPC_R12_WEATHER_LOG=<s>` | строка журнала каждые <s> c (по умолчанию 5) |
| `SSPC_R12_WEATHER_FILE=<path>` | журнал (по умолчанию `<logs>\weather.log`; `tools\r9\r9run.ps1` копирует его в прогон) |

Как работает:
* Проба на входе 0x59cf80 (главный поток игры), логика — после оригинала. Счётчик-проба на 0x597ec0. Все функции,
  на смысл которых опирается инструмент, закреплены хешем тела (0x59cf80, 0x597ec0, 0x1b8e60, 0x1ba7c0, 0x598b50,
  0x598ea0, 0x59d560, 0x190c90, 0x59be90): при несовпадении инструмент не ставится.
* Перед записью — строка `original:` со всеми полями §1.2; запись; на следующем кадре `verify:` (поле прочитано назад
  + итоговая мокрота 0xe87c80 = записанной, если нет оверрайдов с мокротой); каждые LOG c — состояние, итоговая
  мокрота, число вызовов прохода мокроты, оверрайды.
* Не вмешивается (и откатывает уже записанное), пока: показывается ролик (`FullScreenMovieShowing`), шаг игры
  0xe16298 = 0 дольше 2 c (пауза, меню, загрузка), нет TOD / стоит ensured-заглушка, запрошенный TOD ≠ текущему,
  взведены флаги перехода; применяет только после 3 c безопасного состояния и при идущем шаге игры. Каждое такое
  событие — строка `unsafe:` в журнале.
* Откат — только если объект ещё зарегистрирован под тем же id и в поле лежит записанное значение (иначе журнал
  «changed by the game», значение игры не трогается). Если игра сама сменила WETNESS_LEVEL — инструмент отпускает.
* Сохранение игры не вызывается; пишутся только два float в объекте TOD текущей загрузки. WETNESS_LEVEL/PUDDLE —
  данные пакета TOD, в сохранение не попадают [A] (сохраняется только id TOD, world+0x390).
* Откат на выходе — шаг завершения `Lifecycle::AddExitStep(Reports)` (первая стадия, пока игра ещё идёт, до бэкапа
  сохранений). `std::atexit` не годится: упорядоченный выход заканчивается ExitProcess без atexit [E: в журналах
  11bdaa2 нет строки `exit:`, с исправлением есть `exit: 1 applies, 1 restores`].
* **Цена инструмента.** VirtualQuery на адресном пространстве гостя дорог (~1 ТБ резервов, commit on demand:
  RegionSize считается обходом страниц) — единицы мс за вызов [E]. Поэтому на кадре VirtualQuery нет: объект
  текущего TOD и его запись проверяются один раз до смены TOD, имена и указатели оверрайдов — кешируются, строки
  проверяются постранично; откат текущего объекта — без обхода реестра. Своя стоимость пишется в журнал:
  `tool (<мкс>/frame, max <мкс>)`. Обход реестра (≈0,8 с, `registry (time of day loaded)`) остаётся один раз на
  загрузку мира — во время загрузки, когда инструмент и так не вмешивается.

| ночь, сухие поверхности | `neon` | `SSPC_R12_WEATHER=dry` |
| (миссия с дождём, перезагрузки ~20 c) | `rainmission` | только для проверки устойчивости |

Для замеров: `SSPC_R12_WEATHER_AT=<s>` после выхода в мир (≥ 45 c), без `_UNTIL` — состояние держится до выхода.
Сравнивать состояния **внутри одной сцены** (dry vs log); разные сцены = разные сохранения, места, NPC и миссии —
сравнимы только качественно.

## 5. Ограничения и НЕ ПРОВЕРЕНО

* Смену TOD (день↔ночь, дождь↔ясно) на лету инструмент не делает и делать не может без перезагрузки мира [A];
  состояния TOD — только сохранениями. Частицы дождя не управляются (данные пакета TOD [H]).
* WEATHER_KIND, VISIBILITY, туман, ветер, часы — только журнал; запись не проверялась [не проверено].
* Флаг letterbox/реалтайм-катсцен не найден: защита — ролик, остановленный шаг игры, загрузка/переход TOD. Катсцены
  на движке при идущем шаге игры инструмент не распознаёт [не проверено].
* Оверрайды с мокротой (зоны/скрипты) смешиваются с полем; `verify` их учитывает, но управлять ими нельзя. В
  проверенных сценах активных оверрайдов с мокротой не было (один раз 0,000×0,00 в rainmission).
* Счётчики активных источников света — у агента lights (`SSPC_R12_LIGHT_CENSUS`); счётчик машин не найден.
* НЕ ПРОВЕРЕНО: `rainday` (16-09-18) с инструментом на маршрутах fight/traverse; mine/video с записью.
