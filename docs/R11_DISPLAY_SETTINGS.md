# R11 display — раздел «Экран» в меню настроек

Ветка `feature/r11-display` (worktree `E:\SecondSonPC-r10-sysrt`, база `24984ed`). Данные проверок:
`E:\research\r11\runs\display\`. Метки: [E] измерено, [A] анализ кода, [H] гипотеза.

## Что в меню (Esc → «Настройки» → «Дополнительные настройки» → «Экран»)

| Строка | Значения | Ключ settings.toml | Как применяется |
|---|---|---|---|
| **Окно** | | | |
| Режим окна | Оконный / Без рамки (на весь экран) | `[Display] fullscreen` + `fullscreenMode` | сразу, с диалогом «Оставить изменения?» (15 с, иначе откат) |
| Размер окна | пресеты, до размера монитора | `width`, `height` | сразу, с подтверждением |

| **Кадры** | | | |
| Вертикальная синхронизация | Вкл. / Выкл. / Выкл., без разрывов (Mailbox) | `presentMode` (`fifo` / `immediate` / `mailbox`) | свой бэкенд: сразу (swapchain пересоздаётся); мост shadPS4: после перезапуска |
| Ограничение FPS | 60 (vblank PS4), 30, 40, 50, 60, 90, 120, 144, 165, 240, без ограничения | `frameRateLimit` | сразу (существующий лимитер VideoOut) |
| **Картинка игры** | разрешение (+ размер монитора), соотношение сторон, HUD… — без изменений, кроме разрешения монитора в списке | | |

Отдельные строки «Полный экран» и «Тип полноэкранного режима» убраны со страницы: их заменяет «Режим окна»
(ключи и F11 остались прежними).

### Вертикальная синхронизация
- «Вкл.» = `VK_PRESENT_MODE_FIFO_KHR`.
- «Выкл.» = `IMMEDIATE`, если поверхность его поддерживает, иначе `MAILBOX` (так выбирал презентер и раньше).
  В списке при отсутствии IMMEDIATE рядом пишется «(здесь: Mailbox)», в справке — «Сейчас: <режим> (монитор
  поддерживает: …)». Обещания «без синхронизации вообще» нет.
- «Выкл., без разрывов (Mailbox)» — прежнее значение `mailbox` (умолчание поставляемого `SecondSonPC.toml`) осталось
  отдельным пунктом, значения в файлах не мигрируются и не теряются.
- Смена на лету [A]: меню → `Settings::Service` → applier `settings_host.cpp` → `Gpu::Native::SetPresentMode` →
  атомарный запрос презентеру; поток презентации перед следующим `Present` выполняет `Recreate()`: все слоты
  презентации отработаны (`WaitSlot`), новый swapchain создаётся с `oldSwapchain` (у FSR FG — замена его swapchain
  через тот же путь, что и переключение FG), Reflex переподключается внутри `CreateSwapchain`. Если окно свёрнуто —
  swapchain с новым режимом создаётся при разворачивании.
- Лог: `native presenter: present modes <список>; wanted X, using Y …` (при создании и каждой смене режима) и
  `native presenter: vertical sync setting -> X: swapchain recreated (A -> B)`.
- Скорость симуляции, vblank гостя, звук и таймеры игры не трогаются.
- Мост shadPS4 не умеет менять режим на лету: там `EffectiveApply` = Restart и меню пишет «после перезапуска».

### Ограничение FPS
- Только существующий лимитер (`VideoOut` g_pacing, `Gpu::Native::SetFrameLimit`) — второго нет.
- Добавлены 40 и 50. `console`, `240`, `unlimited` и любое целое 20..1000 из toml (`75`) остаются валидными:
  `Desc::accepts`; значение не из списка показывается в списке как «75 (из файла настроек)», пока выбрано.

### Режим окна
- Оконный / Без рамки — на базе `fullscreen` + `fullscreenMode=borderless`.
- «Эксклюзивный» не предлагается: Vulkan-эксклюзива (`VK_EXT_full_screen_exclusive`) в рендерере нет, SDL3
  «exclusive» = полноэкранный режим в режиме рабочего стола, который только сворачивается при Alt+Tab [A]. Если
  `fullscreenMode = "exclusive"` задан в файле — он сохраняется и виден в строке как «Эксклюзивный (SecondSonPC.toml)»
  серым с объяснением; стрелки и список уводят на рабочие варианты.
- HDR/VRR не добавлялись.

### Разрешение и монитор
- Монитор: реальный список дисплеев SDL; одинаковые имена различаются как «Имя (2)»; подпись — разрешение рабочего
  стола в пикселях и частота, отметка основного.
- Разрешение: в список добавляется собственный размер монитора окна (если его нет среди пресетов), пресет с таким
  размером помечается «— как у монитора». `resolution = "1366x768"` из файла валиден (`Desc::accepts` →
  `Engine::Render::ParseSize`).

### Подтверждение с автооткатом
Режим окна, размер окна, монитор — через существующий `Modal::ConfirmDisplay` (15 с, откат по таймеру, по Esc и при
закрытии меню во время вопроса). Вертикальная синхронизация и лимит FPS окна не меняют — без диалога.

## Совместимость
- Первый запуск после обновления: те же значения, что и раньше (умолчания кода и `game/SecondSonPC.toml` не менялись:
  `presentMode="mailbox"`, `fullscreenMode="borderless"`, `frameRateLimit="60"`).
- Новые поля `Desc`: `live_needs` (Live только при наличии capability, иначе Restart) и `accepts` (доп. значения
  Choice). Новая capability `PresentModeSwitch` выставляется в `bootstrap.cpp` только собственным бэкендом.

## Диагностика
`SSPC_DIAG_DISPLAY_SWITCH=<сек>:vsync=fifo|immediate|mailbox;<сек>:limit=60;…` — то же, что делает меню, через
`Settings::Service::Set` в заданные секунды после старта (плюс пауза прекомпилятора). Пишет WARNING в лог. Только для
автоматических проверок и замеров типа B; без переменной ничего не делает.

## НЕ ПРОВЕРЕНО
- Смена VSync при включённой генерации кадров FSR 3.1 / DLSS FG (путь замены swapchain FFX) и с активным Reflex
  в живой игре — на стенде прогоны без FG; код [A] идёт через тот же `Recreate()`/`CreateSwapchain`, что и смена
  размера окна.
- Поверхность без IMMEDIATE (запасной Mailbox и подпись «(здесь: Mailbox)») — только автотест меню; на стенде
  IMMEDIATE есть.
- Два и более мониторов, мониторы с масштабом DPI ≠ 100 % (подпись в пикселях через `pixel_density`) — на стенде один
  монитор 100 %.
- Мост shadPS4 (`--gpu-backend bridge`): VSync «после перезапуска» — только автотест сервиса.
- Геймпад в меню — навигация общая с клавиатурой (`Nav`), отдельно на этой странице не прогонялась; мышь — тоже.
- Ручная игра с изменёнными настройками дольше нескольких минут.

## Риски
- Пересоздание swapchain на лету — между двумя present, после `WaitSlot` всех слотов; при ошибке создания — лог
  `NOT recreated` и прежнее поведение `Recreate()` (как при изменении размера окна).
- `SSPC_DIAG_DISPLAY_SWITCH` в автоматическом прогоне дополнительно выставляет capabilities хоста (только с
  переменной).
- Строки `display.fullscreen` / `display.fullscreenMode` больше не отдельные (`own_row = false`); общий код меню
  (`settings_menu.cpp`) — новая строка `Row::Kind::WindowMode`, `Desc::live_needs`, `Desc::accepts`,
  `Service::EffectiveApply` (описано в `E:\research\r11\SHARED_NOTES.md`).
